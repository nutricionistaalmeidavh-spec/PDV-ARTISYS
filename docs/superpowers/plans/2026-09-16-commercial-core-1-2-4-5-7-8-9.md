# ArtiSys PDV Commercial Core 1/2/4/5/7/8/9 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the selected commercial-core roadmap items for ArtiSys PDV 1.4.0 without introducing mandatory cloud or paid dependencies.

**Architecture:** Extend the existing local-first SQLite runtime with focused domain services. Inventory remains authoritative in `InventoryService`, finance in `FinanceService`, and aggregate reporting in `ReportingService`; new services compose those authorities instead of mutating their tables directly. API/UI follow the existing operational-page and router patterns.

**Tech Stack:** Node.js >=22, `node:sqlite`, Electron, plain JavaScript/CommonJS, existing local HTTP API, existing QA runtime.

**Spec:** `docs/superpowers/specs/2026-09-16-commercial-core-1-2-4-5-7-8-9-design.md`

## Global Constraints

- Mandatory/core functionality stays R$0, local-first and self-hosted.
- No remote API is required for Pix generation or confirmation.
- No direct stock balance mutation outside `InventoryService`.
- Gift-card plaintext codes are never stored; only hashes are persisted.
- Replenishment is suggestion-only and never creates purchase orders silently.
- Target commercial version is `1.4.0`.
